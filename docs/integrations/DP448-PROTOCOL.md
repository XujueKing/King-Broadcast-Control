# DP448 原生双向通讯 · 2026-09-10

已验证的设备：COM3 / 115200 8N1，ID 1，身份返回 `XTA DP448 V3.01 `。
仅此型号/版本开放控制。AudioCore 与 KINGCLUB 不得同时占用串口。

## 当前实现范围

- Rust 直接打开串口，不依赖 AudioCore 或 Python 常驻。
- 读取 8 路输出名称、增益、延时和设备联动组。
- 明确点击后写入增益或延时，再读取完整输出参数块核验；只有预期字段和联动输出改变才返回成功。
- 会话 epoch 和参数块摘要防止旧连接、旧参数写入；错误释放串口，不自动重发。
- 页面每秒读取一次，上一读取未完成不重叠；未连接或退出页面不持续读取设备。
- 布局/距离/离线草稿不自动写入设备。
- 分频、EQ、静音、极性和限幅的原生控制仍未完成，不属于本次已验证范围。

## 报文证据

通过 AudioCore 的 localhost TCP→COM3 临时转接捕获“Just Connect”和“Refresh from Connected Units”。写命令先在**完全不连接串口的模拟器**中捕获，再做实机微量验证。没有向设备发送整套历史工程。

身份请求 `B0 01`；响应以 B8 开始、FF 结束，ID 后为 ASCII 型号固件。

扩展请求：`F0/F1 lenHi lenLo 78 01 00 command payload checksum`。
长度为整帧去掉首字节，按两个 7-bit 字节表示；校验为此前全部字节之和的低 7 bit。
F1 是 AudioCore 捕获的参数写命令前导，本实现仍以完整回读而非该前导或 ACK 作为成功依据。

输出读取：`F0 00 0A 78 01 00 32 00 00 00 25`。
响应 A8，长度计数不含首字节和末尾 FF；校验不含 checksum/FF。
命令后为 7-bit 打包数据，每组 mask + 最多7个低7位字节，mask 第 i 位还原第 i 个字节最高位。
实机最后一组 mask 的未使用位可能非零，不能据此拒绝合法帧。

V3.01 输出块解包后为685字节：

| 偏移 | 内容 |
| --- | --- |
| 2 + 输出索引 | 联动组单比特标识；相同标识的输出共同改变 |
| 18 + 索引×2 | 有符号小端增益，0.1dB |
| 34 + 索引×3 | 24位小端延时，12288单位/ms |
| 621 + 索引×8 | 8字节 ASCII 输出名称 |

增益写 command 02；延时写 command 01。payload 解包后为通道号（OUT1=5…OUT8=12）加对应小端数值，再按上述方式打包。
软件当前允许 -60…+12dB / 0…1000ms；这是本阶段软件控制范围，不是完整设备能力声明。

## 实机验证

OUT1 增益 -9.0→-9.1→-9.0dB，OUT2 同步变化；完整输出块仅偏移18、20改变，恢复后与原块逐字节一致。最初“单输出变化”断言因此失败，记录促成联动组处理；未将其误报成独立控制成功。

OUT1 延时 172032→172020→172032单位（14→13.9990234375→14ms），OUT2联动；仅偏移34、35、37、38变化，恢复后完整输出块逐字节一致。

保存实机输出块和原帧为 Rust 测试 fixture。原工程备份：`../hardware/DP448-LIVE-2026-09-10.xaa`，未被模拟器参数覆盖。

以上是通讯及参数回读验证，不代表全场声学校准完成。音箱到 OUT 的实际线路仍须按现场确认。

桌面验收：打包后的 Tauri 应用通过 COM3 直接识别设备并稳定回读；中控“应用音量”按钮完成 -9.0→-9.1→-9.0dB，切换 OUT2 显示同步 -9.1dB，恢复后延时仍为14ms。退出处理器页面后直接串口探针可重新打开 COM3，证明页面清理释放串口。7项Rust协议测试、3项布局测试与前端构建通过。
