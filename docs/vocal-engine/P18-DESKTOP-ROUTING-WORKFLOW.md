# P18 — 桌面端通道映射工作流

## 已实现

设置页的 AI 人声补音区域增加 Qu-16 USB / ASIO 通道映射面板：

1. **发现驱动**：桌面端调用独立 Vocal Engine 的 P17 发现命令。
2. **逐路确认**：分别显示 Mic1/Mic2/Mic3 的 Qu 输入、ASIO 输入索引和处理返回索引。
3. **保存映射**：保存到 Tauri `app_data_dir/vocal-routing.json`，启动后可重新读取。
4. **现场解除阻断**：当前保持禁用，只有实体 Qu-16 逐路信号追踪完成后才能开放。

## 安全约束

- 离线演练不会启动输入流或音频输出。
- 离线演练不会写入 Qu-16 参数。
- 后端保存前再次校验三路通道唯一性和虚拟证据。
- 虚拟报告只要声称 `hardwareReady=true`、`physicalHardware=true` 或 `qu16MappingVerified=true` 就拒绝保存。
- 前端不接受字符串形式的真假值来解除现场阻断。
- 当前保存的是离线映射，不代表现场 USB Patch、PA 返回或 DP440 路由已验证。

## 验证结果

- Tauri Rust：62 项测试通过。
- 通道映射前端与命令契约：14 项测试通过。
- Vite 生产构建通过。
- 现场 Qu-16 声音验证未执行。

## 现场下一步

连接 Qu-16 USB-B 后，在主输出静音或安全监听条件下逐路追踪 Mic1、Mic2、Mic3，确认输入与处理返回，再生成 `onsite_signal_trace` 证据并开放现场确认按钮。
