# P28：参考人声应急补位

## 结论

P0–P27 已有的 `repair_candidate` 只会把实时 DSP 修音比例提高到上限，无法在歌手断音、高音完全唱不上去或漏唱时继续产生完整歌词与音符。P28 增加一条预先制作、与歌曲时间轴对齐的参考人声分轨，由 Deck“补音”开关控制，并按真人声检测与演唱评分连续自适应混合。

当前实现的参考人声是歌曲包中的 `vocals.flac`，通常就是分离后的原唱。它不是生成式模型，也不会自动变成现场歌手的性别或音色。

## 实时规则

- Deck“补音”关闭时参考女声始终为零；打开后，仅在 `reference.json` 表示当前时间存在演唱时允许补位，间奏保持关闭。
- 桌面软件试听不依赖现场输入链：补音开启且歌手参考已绑定时，独立 mpv 参考层跟随当前主导 Deck 的播放、暂停、Seek、交叉推子和 CUE 输出。最大补音时参考层与伴奏共用 Deck 输出增益；参考轨自身的制作响度差负责保持人声低于伴奏。该层只读取离线参考轨并返回 `physicalAudioStarted: false`，不会武装 Qu-16 实时输入/返回 Vocal Engine 链路；一旦现场 Vocal Engine 已显式武装并开始物理音频，mpv 试听层立即退出，避免固定参考声与真正自适应输出叠加。
- 应唱位置没有检测到真人声时，参考女声自动升到当前最大目标比例，因此无人演唱也能补完整歌词与旋律。
- 检测到真人演唱后立即启用评分，并同时连续跟踪真人包络：真人低于 `0.012` 线性幅度时仍保持最大补位；从 `0.012` 到 `0.080` 之间随真人变响连续减少；达到 `0.080` 后，响度本身不再要求补位。
- 评分需求与响度需求取较大值：`40` 分及以下使用最大补音比例，`70` 分及以上不再由评分要求补位，二者之间连续线性变化。因此小声但唱准、响亮但唱偏两种情况都会得到需要的支持；只有真人足够响且评分高时才退到零。
- 参考人声增加时使用 `32 ms` 淡入、减少时使用 `180 ms` 淡出，最大混合比例为 `92%`。
- 默认参考分轨增益为 `0 dB`，与桌面试听的最大补位一致；物理链路仍默认不启动，现场首次武装测试可显式从 `--reference-rescue-gain-db -12` 开始再逐步校准。
- FLAC 在启动实时流之前完整解码为单声道内存；现有 44.1 kHz 歌曲包会在此阶段重采样到 48 kHz，音频回调内不读文件、不加锁、不进行堆分配。
- `referenceRescueMixLatest` 与 `referenceRescueActive` 进入实时指标，便于 UI 明确显示是否正在用参考人声补位。

## 安全与产品边界

物理实时链路默认关闭，必须显式提供：

```text
--enable-reference-rescue
--reference <reference.json>
--reference-vocal <vocals.flac>
```

这不是最终的“像当前歌手唱准以后”的方案。男原唱歌曲由女歌手演唱时，直接补 `vocals.flac` 会暴露男原唱；女原唱歌曲由男歌手演唱同理。不能用简单 Pitch/Formant 变换冒充本人音色。

正式的本人音色补位需要单独阶段：

1. 获得歌手本人明确授权并采集声音样本；
2. 建立可撤销、可删除的 Vocal Profile；
3. 在演出前离线生成本人音色的完整理想参考人声；
4. 与歌曲 `reference.json` 使用同一 48 kHz 时间轴；
5. 现场只做检测、对齐、选择和交叉混合；
6. 无本人参考包时只允许 DSP 修音，原唱补位必须由操作员另行确认。

## 仍需现场验证

- Deck 00:00 与 Vocal Engine 参考游标的同步及 seek/暂停/循环重定位；
- Qu-16 USB 输入、处理返回和干声回退的唯一通道路由；
- 参考分轨与现场人声的响度、相位和听感；
- 耳返与主扩是否需要不同策略；
- 实际物理 RTT、啸叫保护与断线撤销。

完成以上验证前，P28 只能低电平、单路、人工监护测试，不能宣称已达到无感生成式补音。
