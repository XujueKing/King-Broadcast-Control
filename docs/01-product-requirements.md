# 产品需求

状态：首版范围讨论中

版本：0.2

## 1. 产品目标

为 KING CLUB 提供一套运行在 Windows 主控电脑上的本地播控软件，统一完成视频、音频、LED 大屏、调音台和灯光场景的日常控制。系统必须适合营业现场快速操作，并为后续手机点歌、弹幕、祝福文字和多屏控制预留能力。

## 2. 已确认现场条件

### 操作端

- Windows 主控电脑
- LED 主屏通过现有视频处理系统即插即用，作为普通 Windows 第二显示器连接
- 操作员在主控界面查看实时预览并执行播控

### 显示设备

- 舞台异形 LED 主屏一块
- 已确认总外框：宽 5120 mm × 高 5760 mm
- 下部 B 区：宽 5120 mm × 高 2880 mm
- 上部 A 区：宽 2560 mm × 高 2880 mm，位于 B 区上方中央
- P2.5 LED 模组：320 × 160 mm，单模组 128 × 64 px，1/32 扫描
- B 区为 16 × 18 个模组，对应 2048 × 1152 px
- A 区为 8 × 18 个模组，对应 1024 × 1152 px
- 外框逻辑画布推算为 2048 × 2304 px，上半区左右各有 512 × 1152 px 的非显示区域
- 实际发光像素约 354 万
- 现场已经能够直接播放普通 Windows 视频，画面可覆盖整个异形发光区域
- DJ 台另有一块长条 LED 小屏，首版是否接入待确认
- 架构需预留多显示输出，但首版以主屏稳定输出为优先

注意：以上像素布局由模组参数推算。软件不直接配置 LED 模组或发送卡，而是把现有 LED 视频处理系统当作普通 Windows 显示器使用。首次启动时自动读取 Windows 报告的实际分辨率、刷新率、显示器标识和位置并保存；操作员可在设置中重新选择输出屏。

### 音频设备

- Allen & Heath Qu-16 数字调音台
- 软件需要播放歌曲音频
- 需要像 KTV 一样切换原声/伴唱
- 需要控制与歌曲播放相关的调音台功能，具体通道和动作待确认

### 音乐内容来源

- KING CLUB 当前没有自有歌曲库，希望顾客点歌时能搜索并获取歌曲
- 候选来源为 QQ 音乐、酷狗音乐或具备合法商用授权的其他曲库供应商
- 普通个人会员、客户端下载和离线缓存不视为酒吧商用授权
- 首版不得使用非官方私有 API、抓包、爬虫、破解缓存或绕过 DRM 的下载方式
- 只有取得供应商书面商业授权和正式接口文档后，才接入在线搜索、试听、缓存或下载
- 商务授权必须明确覆盖：酒吧公开播放、顾客点歌、软件内搜索/播放、本地缓存、歌词/封面展示，以及原声/伴唱或 KTV MV

### 灯光设备

- Avolites Tiger Touch Pro 灯光控制台
- 灯光节目继续由灯光台保存和执行
- 软件需要为歌曲绑定预设灯光，并在歌曲开始或人工点击时触发

## 3. 首版用户

主要用户暂定为主控电脑前的现场操作员。账号、多人操作和权限暂不作为首版核心，但危险操作仍需要防误触。

后续用户包括顾客或工作人员使用手机完成点歌、发送弹幕及生日/欢迎祝福。

## 3.1 主控制台页面

控制台底部提供 6 个固定主页面入口：首页、音乐管理、视频管理、灯光管理、调音台和 Avolites Tiger Touch Pro。页面切换不得中断歌曲、LED 输出或外设连接。

## 4. 首版核心流程

### 4.1 营业日节目

系统提供两类歌单：

- 常规歌单：星期一至星期日共 7 个，每天一份默认常规播放内容
- 特别歌单：不限数量，用于活动、节日、主题夜、包场或临时节目

营业流程：

1. 系统根据本地日期推荐当天的常规歌单，操作员确认后开始播放。
2. 每份正式歌单的可播放总时长至少覆盖 8 小时。
3. 每首歌曲可关联歌曲音频/MV、背景视频和灯光预设。
4. 操作员可在营业前编辑歌单，也可在播放中调整尚未播放的队列。
5. 特别歌单可临时替代常规歌单，或作为一段节目插入当前队列。
6. 特别歌单结束后，可选择返回原常规歌单的断点位置或继续下一首。
7. 播放时同步执行已绑定的视频、音频与灯光触发。

常规歌单按星期保存，但允许复制为新版本或从其他星期复制内容；特别歌单可以设置名称、标签、适用日期和备注。

### 4.2 歌单编辑

- 新建、复制、重命名、删除和归档特别歌单
- 编辑星期一至星期日的默认常规歌单
- 从歌曲库搜索并批量加入歌曲
- 拖拽排序、批量移除、去重和多选移动
- 显示歌曲数量、单曲时长、累计时长和预计结束时间
- 低于 8 小时时给出醒目提示，但允许保存草稿
- 检测文件丢失、授权失效、音轨缺失、视频缺失或灯光绑定失效
- 设置单曲是否允许随机、是否跳过、默认原声/伴唱及转场方式
- 导入/导出歌单配置；导出内容不复制无权分发的媒体文件
- 保存编辑历史，并支持撤销未发布修改
- 点击歌曲条目打开配置面板，编辑音频来源、画面来源、原伴唱方式、灯光预设和转场
- 支持在列表内直接修改显示名称、歌手、备注和播放启用状态
- 支持复制歌曲条目后使用不同的视频或灯光组合

歌单采用“草稿 → 已发布”流程。营业播放使用已发布版本，避免后台编辑立即改变正在播放的队列；操作员可明确选择“应用到当前播放”。

完整歌单编辑、搜索、上传、新建和批量管理只在“音乐管理”页面提供。首页左侧只浏览已发布歌单、查看歌曲信息并向 1号/2号 Deck 装载候选。

### 4.3 歌曲媒体组合

歌曲的声音和画面分别配置，支持以下首版组合：

| 音频来源 | 画面来源 | 使用场景 |
| --- | --- | --- |
| MP4 内置音频 | 同一个 MP4 的视频 | 直接播放完整音乐视频 |
| MP4 内置音频 | 自有视频 | 保留歌曲声音，用 KING CLUB 视频替换原画面 |
| MP3/FLAC/WAV | 自有视频 | 独立歌曲音频配合循环或指定视频 |
| MP3/FLAC/WAV | 静态图/默认背景 | 没有匹配视频时的安全回退 |

配置规则：

- `音频来源`决定实际送往调音台的声音
- `画面来源`决定 LED 主屏内容
- 自有视频较短时可循环，歌曲结束时视频随歌曲停止
- 自有视频较长时默认在歌曲结束时截断，也可配置结束行为
- 音频和视频从共同起点启动，并持续监测同步偏差
- MP4 被替换画面时，不渲染其视频轨，但继续使用所选音轨
- 缺少自有视频或自有视频加载失败时，可配置回退到原 MP4 视频或默认背景
- 每个歌单条目可以覆盖歌曲库中的默认媒体组合，不影响其他歌单使用同一首歌

### 4.4 歌曲播放

- 查看当前歌曲和后续歌单
- 播放、暂停、继续、停止、上一首、下一首
- 播放进度条、已播放/剩余时间和指定位置跳转
- 单曲循环、顺序播放、随机播放
- 原声/伴唱切换
- 原 MP4 画面/自有视频/默认背景实时切换
- 从视频库临时选择另一个视频替换当前画面
- 音量、静音及淡入淡出控制；实际开放范围需与 Qu-16 通道方案共同确认
- 类似 DJ 台的双 Deck 播放：Deck A 播放当前歌曲，Deck B 预加载下一首
- 手动 Crossfader 在两首歌曲之间平滑切换
- 自动过渡：当前歌曲结束前按设定时长淡出，同时下一首淡入
- 查看歌曲关联的视频和灯光预设
- 临时覆盖某首歌曲的关联项
- 临时插播一首歌，结束后返回原队列位置
- 标记下一首、跳过某首和移除尚未播放歌曲
- 显示当前歌单已播放时长、剩余时长及预计结束时间
- 软件重启后恢复歌单、当前曲目、播放位置和原播放模式，由操作员确认后续播

切换控制要求：

- 原声/伴唱切换只切换声道或音轨，不重新开始歌曲和画面
- 原视频/自有视频切换只改变画面，歌曲音频连续播放
- 切换到自有视频时，可选择从视频开头播放或按歌曲当前进度对齐
- “下一首”触发前允许设置音频淡出、视频转场和灯光切换时间
- “停止”与“紧急黑场”是不同操作：停止歌曲后显示待机画面；黑场立即关闭主屏内容
- 控制指令执行中、防重复点击和失败状态必须有明确反馈

### 4.5 双 Deck 与平滑过渡

首版采用简化的先锋 DJ 台工作流，不实现专业打碟台的全部效果器和搓碟能力：

- Deck A 和 Deck B 分别加载一首歌曲，只有一个为当前主 Deck
- 待播 Deck 在切歌前完成文件检查、解码预热、音轨和视频加载
- Crossfader 支持鼠标拖动、点击切换以及可配置快捷键
- 自动过渡时长可配置，默认建议 5 秒；单曲可覆盖默认值
- 支持立即切换、短淡化、标准交叉淡化三种预设
- 自动模式下，系统根据歌曲剩余时间触发下一首预加载和过渡
- 手动模式下，操作员决定何时启动并控制 Crossfader
- 过渡完成后，旧 Deck 停止并清理，再预加载新的下一首
- 每首歌可设置 `IN` 开始点和 `OUT` 混出点，跳过不需要的前奏/过门、空白和结尾
- 待播 Deck 可从当前歌单后续歌曲或整个音乐库选择候选

音频过渡：

- 使用等功率交叉淡化，减少中点听感突然变小
- 原声/伴唱状态分别属于每个 Deck，切换时不得串错音轨
- 两首歌音量差异过大时给出提示；响度标准化是否自动应用待验证
- 首版不承诺自动 BPM/节拍对齐、变速不变调、搓碟或专业 DJ 效果
- 首版允许根据静音/低能量提出 IN/OUT 建议，但最终点位可人工试听和校正

视频与灯光过渡：

- 视频支持硬切、交叉淡化和先黑后切
- 自有视频继续遵守当前歌曲音频的播放时钟
- 灯光可在过渡开始、中点或结束时触发下一首预设
- 如果灯光触发失败，音频过渡继续完成并显示告警

### 4.6 视频播放

- 浏览本地视频库
- 缩略图/名称搜索与分类
- 点击视频直接在主屏播放
- 主控界面显示低延迟实时预览
- 支持暂停、继续、停止、循环
- 支持异形屏安全区/遮罩，避免内容落入无 LED 区域
- 支持纯色视频、待机画面和紧急黑场
- 首页右上区域以静态缩略图和时长展示视频，不显示文字介绍；单击立即替换 LED 当前画面
- 首页快速视频默认不输出文件自带音频，避免与当前歌曲重叠

### 4.7 灯光控制

- 展示已配置的灯光预设组合
- 点击预设触发 Tiger Touch Pro 内已编程的 Cue/Playback
- 歌曲可绑定一个默认灯光预设
- 自动触发失败时应提示，并允许人工重试或改选预设
- 首版不直接接管灯具 DMX/Art-Net 输出，避免与灯光台争用控制权
- 首页右下区域提供灯光预设与常用灯光快捷选择，作为 Tiger Touch Pro 的简化操作区

### 4.8 大屏文字

- 输入文字并显示到主屏
- 支持欢迎语、生日祝福和临时通知
- 至少支持字体大小、颜色、位置、持续时间和进入/退出方式
- 操作端发送前可预览
- 手机弹幕属于后续阶段，需要内容审核、频率限制和一键关闭

### 4.9 音频与调音台

- 播放歌曲音频并跟随歌单控制
- 切换原声与伴唱音轨
- 向 Qu-16 发送已批准的控制动作
- 首版建议仅开放必要动作，例如指定通道静音、音量或场景调用
- 软件显示的调音台状态应尽量与设备实际状态双向校准

## 6. 音乐版权与供应商验收条件

音乐供应商需要书面确认以下事项，否则不能成为正式播放源：

1. 授权地域和有效期覆盖 KING CLUB 实际经营地点及营业时间。
2. 授权场景明确包含酒吧等商业场所公开播放，而不只是个人欣赏。
3. 允许第三方播控软件通过官方 API 搜索、播放，并说明能否下载或仅能加密缓存。
4. 明确歌曲、歌词、封面、MV 的权利范围。
5. 明确是否提供 KTV 原声/伴唱双轨、伴奏版或双音轨 MV。
6. 提供曲库覆盖率、上下架通知、并发/设备限制、离线时长和故障 SLA。
7. 提供正式 SDK/API、测试环境、鉴权方式和费用方案。
8. 明确顾客手机点歌是否属于授权范围。

若在线供应商临时下架歌曲、授权到期或网络中断，系统应保留合规的本地应急曲库和清晰的不可用提示，不能尝试绕过供应商限制。

## 7. 非功能要求

- 核心播放和控制不依赖公网
- 软件异常不能把 Windows 桌面或报错窗口暴露到 LED 主屏
- 主屏播放进程异常时应进入安全画面或黑场
- 危险操作需要明确反馈和适当确认
- 每条外设指令记录发送时间、目标、结果和错误原因
- 设备断线后能自动检测，恢复连接后校准状态
- 支持营业时长的连续稳定运行；具体压力测试时长待确认
- 单次歌单至少支持 8 小时内容；验收需完成不短于 8 小时的连续播放测试
- 8 小时测试期间不得发生崩溃、黑屏、明显音画不同步或无法自动恢复的播放故障
- 连续切歌应完成预加载；正常素材和设备条件下不得出现非预期静音间隙或 Windows 桌面闪现

## 8. 下一轮必须确认

1. 是否由 KING CLUB 联系腾讯音乐/酷狗的商务版权合作，取得 B 端曲库、公开播放及第三方 API 的书面方案？
2. 供应商能否提供原声/伴唱双轨或 KTV MV，而不仅是普通音乐流？
3. Qu-16 当前固件版本、网络连接方式、IP 地址，以及要控制的通道/场景分别是什么？
4. Tiger Touch Pro 的序列号、Titan 软件版本、网络连接方式，以及现有灯光预设保存在哪些 Playback/Cue？
5. DJ 台长条屏的像素分辨率、连接方式，以及首版是否必须显示独立内容？
6. 常用媒体格式、最高分辨率/帧率、单文件大小和素材总量是多少？
7. 常规歌单只按顺序连续播放，还是需要某些歌曲在具体时间点自动开始？
8. 特别歌单结束后，默认返回常规歌单断点，还是继续常规歌单的下一首？
9. 默认自动过渡采用 3 秒、5 秒还是其他时长？
10. 是否需要在后续版本增加 BPM/节拍对齐，还是平滑交叉淡化已经足够？
