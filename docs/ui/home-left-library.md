# `UI-R02 / L` 首页曲库与歌单

状态：已确认

版本：1.9

## 1. 区域用途

首页的 `UI-R02 / L` 是现场操作用的曲库/歌单区域，用于给 Deck 1 或 Deck 2 查看歌单、选择候选歌曲。它不是音乐素材管理页面。

首页 L 区明确不显示：

- 搜索框
- 上传素材
- 新建歌曲或新建歌单
- 批量管理
- 删除、重命名、文件整理等管理按钮

上述功能仅在底部导航的“音乐管理”页面提供。

## 2. 纵向布局

```text
┌────────────────────────────────┐
│ 1号曲库          2号曲库       │  顶部 Deck 切换
├────────────────────────────────┤
│ 周一 周二 周三 周四 周五 周六 周日 │  7 等分常规歌单
├────────────────────────────────┤
│ 情人 七夕 万圣 圣诞 跨年 店庆 活动 │  7 等分节日歌单
├────────────────────────────────┤
│                                │
│ 对应歌单的歌曲列表             │  中部列表
│ 当前播放行高亮                 │
│ 候选/待播状态                  │
│                                │
└────────────────────────────────┘
```

顶部曲库切换和两行歌单按钮固定，中部歌曲列表独立滚动。列表滚动不能让这些切换按钮消失。

L 区底部不设置“加载到 1号 Deck / 2号 Deck”的整条按钮；删除该按钮释放出的全部高度归中部歌曲列表使用，让同屏可见歌曲数量尽可能增加。

1号/2号曲库、星期歌单、节日歌单三行统一采用约 40px 行高，按钮文字垂直居中。

## 3. 顶部 Deck/曲库切换

固定显示两个等宽按钮：

| 编号 | 显示文字 | 对应对象 |
| --- | --- | --- |
| `LIB-01` | 1号曲库 | Deck 1 的候选/播放列表视图 |
| `LIB-02` | 2号曲库 | Deck 2 的候选/播放列表视图 |

交互规则：

- 切换按钮只改变 L 区当前操作目标，不影响正在播放的 Deck
- 顶部选择 `1号曲库` 或 `2号曲库` 只是指定随后歌曲装载的目标 Deck；它不是播放、切台或大厅声音切换命令
- 默认运行态为 Deck 1 `ON AIR`、Deck 2 `READY/待命`；切换到 2号曲库准备下一首时，Deck 1 和当前大厅声音必须保持不变
- 当前选择使用绿色边框、图标和轻微半透明背景
- 如果某 Deck 正在播放，其按钮同时显示 `ON AIR`
- 如果某 Deck 已装载候选，其按钮显示 `READY`
- `ON AIR` 和当前选中是两种状态，可以同时出现在不同按钮上
- UI 保留“1号曲库/2号曲库”文字；数据层实际复用统一歌曲库，分别维护两个 Deck 的运行队列，不复制媒体文件
- 两个按钮下方使用一条贯穿 L 区宽度的直线分割，不使用悬浮卡片间距

## 4. 底部歌单按钮

第一行固定为 7 个常规歌单：

- `PL-W1` 周一
- `PL-W2` 周二
- `PL-W3` 周三
- `PL-W4` 周四
- `PL-W5` 周五
- `PL-W6` 周六
- `PL-W7` 周日

第二行固定预留 7 个等宽特别歌单位置：

- `PL-S01` 情人节
- `PL-S02` 七夕
- `PL-S03` 万圣节
- `PL-S04` 圣诞节
- `PL-S05` 跨年
- `PL-S06` 店庆
- `PL-S07` 活动

规则：

- 点击按钮后，中部立即切换为对应已发布歌单
- 当前歌单按钮使用绿色选中态
- 当天星期按钮可显示弱提示，但不强制切换
- 两行均从左到右完整 7 等分，不使用横向滚动
- 后续增加更多特别歌单时进入音乐管理页编辑，不改变首页固定的 7 个节日按钮位
- 首页只选择已发布歌单，不在此新建、重命名或删除
- 切换浏览歌单不自动替换正在播放队列；装载或应用时需要明确操作

## 5. 中部歌曲列表

列表优先显示现场选择需要的信息：

| 字段 | 必须显示 |
| --- | --- |
| 序号 | 是 |
| 歌名 | 是 |
| 歌手 | 是，使用独立列，不再并入歌曲副信息 |
| 时长 | 是 |
| 视频状态 | 是，以紧凑图标/文字显示 |
| 灯光预设 | 是，以紧凑图标/名称显示 |
| 原声/伴唱能力 | 是，以状态图标显示 |
| Deck 状态 | 是：ON AIR / READY / 未装载 / 错误 |

列表布局规则：

- 歌曲列表禁止横向滚动，所有必显信息必须收纳在 `L` 区当前可用宽度内
- 主列顺序固定为：序号 / 歌曲 / 歌手 / BPM / 时长；歌曲标签仍可显示在歌曲列内，作为歌名下方或旁侧的紧凑副信息
- 列宽随 `L` 区宽度自适应：序号、BPM、时长和状态操作区使用紧凑约束，歌曲列与歌手列共同使用剩余空间
- 窄宽度下歌曲列和歌手列允许弹性收缩，并分别使用单行省略号；禁止通过横向滚动显示完整文本，也不隐藏 BPM、时长或 Deck 状态
- 时长在歌曲未选中时位于数据列最右；当行末显示 Deck 播放圆时，时长与第一个播放圆之间保留约 8 px 安全间距，避免信息和状态标记粘连
- 列表表头与每一行使用相同的列宽计算，调整画布尺寸时不得发生列错位

行操作保持简单：

- 单击选中歌曲
- 双击歌曲行把歌曲装入顶部当前选中的 1号/2号 Deck；也可使用歌曲行内的数字操作直接装入指定 Deck
- L 区不提供底部通栏装载按钮，所有歌曲装载/插播均通过行内操作或双击完成
- 歌曲未选中时不显示插播按钮，BPM 和时长保持正常信息布局；时长始终贴近歌曲行最右侧对齐
- 选中歌曲后，BPM 与时长平滑向左移动，为行末操作区让出空间；移动过程中字段顺序和数值不得跳变
- 让位完成的同时，两个数字操作按钮从歌曲行右侧向左淡入并飞入，分别用于把歌曲装入 Deck 1 或 Deck 2 作为候选；它们不是“立即播放”命令
- 两个数字操作按钮使用较大的正方形圆角按钮形态，界面只显示数字 `1` 和 `2`；悬停提示显示“装载至 Deck 1/2（保持暂停）”
- 取消选择或切换到其他歌曲时，当前行两个按钮反向淡出并向右退出；BPM 与时长随后平滑回到默认位置，时长重新贴行最右
- 动效应短促、连贯且不改变歌曲行高度，建议时长约 160–220 ms；连续切换歌曲时不得造成列表抖动
- 用户启用 Windows“减少动态效果”时可取消位移动画，但仍需保持选中前后的信息和按钮布局清晰
- 插播按钮独立响应点击，不触发歌曲行的选择或双击装载动作
- 无论通过双击还是数字 `1`/`2` 装载，目标 Deck 都必须重置到 `00:00`、完成预热后停留在 `READY/暂停`；不得自动开始播放、不得自动移动 Crossfader、不得切换大厅主输出，也不得改变 C1 的 LED 节目画面
- 装载到 Deck 2 的典型用途是准备下一首：Deck 1 可以继续 `ON AIR`，直到操作员在 C2 手动按下 Deck 2 的播放按钮并手动调节 Crossfader
- 已成功装入 Deck 1 或 Deck 2 的歌曲行立即进入锁定状态，不能再次通过单击进入普通选择态，也不能通过双击重复装载
- 锁定行不显示数字 `1`、`2` 插播按钮，鼠标经过、聚焦或再次点击时也不得触发按钮淡入/飞入动画
- 装载或插播成功后，该歌曲行立即退出普通选择态，移除中性选中样式和临时操作按钮，只保留对应 Deck 的颜色与状态标记
- 当前播放歌曲不允许因误双击而重新加载
- 右键/更多菜单只保留现场需要的“装载、设为下一首、查看详情”

## 6. 当前播放高亮

当前播放行必须明显，但适合暗场：

- 使用半透明翡翠绿背景，例如 `rgba(53, 208, 127, 0.14)`
- 左侧增加 3–4 px 绿色高亮条
- 显示 `ON AIR` 文字和播放图标
- 当前正在播放的歌曲行最右侧显示直径约 `20px` 的实心圆播放标记：Deck 1 使用绿色圆，圆内显示深色 `1`；Deck 2 使用蓝色圆，圆内显示深色 `2`
- 圆内数字使用约 `14px` 字号和接近列表背景的深色，形成数字从实心圆中镂空出来的视觉感；标记不能挤压歌名主体
- Deck 1 与 Deck 2 可以同时播放；若两者播放同一首歌曲，该歌曲行最右侧并排显示绿色 `1` 圆和蓝色 `2` 圆
- 每个播放圆只跟随对应 Deck 的实际播放状态显示；暂停、停止、仅装载或 READY 时隐藏该 Deck 的圆，另一 Deck 若仍在播放则保留其圆
- 歌名使用主要文字色，不使用大面积高亮绿文字
- 鼠标 Hover 不能覆盖或混淆 ON AIR 状态
- 若当前歌曲不属于正在浏览的歌单，在列表顶部显示一条紧凑的“当前播放”摘要，不伪造到当前歌单中

待播歌曲使用更弱的绿色/边框并显示 `READY`；普通选中行使用中性深色，避免与 ON AIR 混淆。

双 Deck 状态允许同时保留在列表中：

- Deck 1 已装载的歌曲使用绿色半透明背景，并显示绿色扬声器图标
- Deck 2 已装载的歌曲使用蓝色半透明背景，并显示蓝色扬声器图标
- Deck 1 与 Deck 2 即使同时装载不同歌曲，两行状态也必须同时可见，不能因切换顶部曲库而清除另一 Deck 的装载标识
- Deck 1 与 Deck 2 允许同时处于播放状态；列表应分别在对应歌曲行显示各自的播放圆，不把其中一个强制降级为待播状态
- 若两个 Deck 装载同一首歌曲，该歌曲行同时显示 Deck 1 与 Deck 2 的独立状态标记，不用单一颜色覆盖其中一个状态
- 普通单击只表示“当前选中”，未装载时使用中性深色背景/边框，不显示绿蓝扬声器图标，避免与 Deck 装载状态混淆
- Deck 颜色标记同时代表该行已锁定；只有当歌曲从对应 Deck 卸载或被其他歌曲替换后，该行才恢复为可选择、可装载状态

## 7. 与 C2 的联动

- L 顶部选择 1号曲库时，歌曲装载目标为 C2 的 Deck 1
- L 顶部选择 2号曲库时，歌曲装载目标为 C2 的 Deck 2
- C2 的 Deck 状态变化实时反映到 L 顶部按钮和歌曲行
- L 区的装载动作只更新目标 Deck 的候选媒体与 `READY` 状态；不会改变另一 Deck 的播放状态、主输出音量、Crossfader 位置或 C1 预览/输出节目
- Deck 播放/暂停与 Crossfader 均只能由 C2 的操作员控制；L 区不提供隐式自动播放、自动淡入淡出或自动主输出切换
- 操作员完成实际播放与过渡后，新的 ON AIR 行自动高亮，但不强制滚动打断操作员当前浏览；提供“定位当前播放”按钮
