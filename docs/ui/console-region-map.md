## 2. 布局关系

```text
┌──────────────────────────────────────────────────────┐
│ UI-R01 / T                                           │
├──────────────────┬───────────────────┬───────────────┤
│                  │ UI-R03 / C1       │               │
│                  │                   │               │
│ UI-R02 / L       ├───────────────────┤ UI-R05 / R    │
│                  │ UI-R04 / C2       │               │
│                  │                   │               │
├──────────────────┴───────────────────┴───────────────┤
│ UI-R06 / B                                           │
└──────────────────────────────────────────────────────┘
```

层级规则：

- 根布局按纵向分为 `T + 主体 + B`
- 主体按横向分为 `L + C + R`
- 中央 `C` 再按纵向分为 `C1 + C2`
- `T` 和 `B` 始终横跨整个控制台宽度
- `L`、`C1/C2`、`R` 共用同一主体高度

## 3.1 `UI-R03 / C1` LED 预览约束

`C1` 已确认为 LED 主屏实时预览，用户提供的 T 形比例为正式比例：

- 逻辑外框：2048 × 2304 px
- 外框宽高比：8:9
- 上半 A 区：1024 × 1152 px，水平居中
- 下半 B 区：2048 × 1152 px，铺满下半部分
- 上方左右非显示区：各 512 × 1152 px
- 预览遮罩：[led-main-screen-mask.svg](../../assets/ui/led-main-screen-mask.svg)

布局规则：

- 预览画布始终保持 `aspect-ratio: 8 / 9`，禁止随 `C1` 容器拉伸变形
- 在 `C1` 内水平、垂直居中，并按 `contain` 方式使用可用空间
- 非显示区域使用纯黑，发光区域显示最终合成画面
- 预览必须与 LED 输出复用同一合成状态、遮罩和安全区
- 预览周围剩余空间属于 `C1` 的留白，不改变屏幕比例
- 可在预览上叠加仅操作员可见的边界、安全区和 A/B 区标识；这些辅助线不得出现在 LED 正式输出
- 后续即使 `L`、`R` 或 `C2` 尺寸调整，`C1` 内的 LED 外框比例仍保持 8:9

## 3.2 `UI-R06 / B` 主导航约束

`B` 已确认为全局主导航栏，详细规范见 [底部主导航](bottom-navigation.md)。该区域始终横排 6 个固定顺序按钮，不改为竖排，不与播放控制条混用。

## 3.3 `UI-R04 / C2` 双 Deck 约束

`C2` 已确认为双 Deck 实时播放和无缝衔接区，详细规范见 [C2 双 Deck 播放控制](c2-dual-deck.md)。Deck 1/2 左右并列，中间放置过渡控制；区域高度调整不能把其中一个 Deck 隐藏到分页或弹窗中。

## 3.4 `UI-R02 / L` 首页曲库约束

`L` 在首页固定为曲库和歌单选择区，详细规范见 [首页曲库与歌单](home-left-library.md)。顶部 Deck 切换和底部歌单按钮固定，中部列表独立滚动；首页禁止出现搜索、上传、新建和批量管理按钮。

## 4. 后续命令格式

以下命令均可准确定位：

- “调整 `UI-R03`，增加主屏预览。”
- “调整 `C1`，预览画面扩大一些。”
- “把 `UI-R06/B` 的控制按钮加高。”
- “交换 `L` 和 `R` 的内容。”

当图片代号和固定编号同时出现但不一致时，以固定编号 `UI-Rxx` 为准，并在修改前指出冲突。
