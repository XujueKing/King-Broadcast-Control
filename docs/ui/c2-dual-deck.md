# `UI-R04 / C2` 双 Deck 播放控制

状态：已确认

版本：1.18

## 1. 区域用途

`UI-R04 / C2` 固定为双 Deck 实时播放与无缝衔接区。区域同时展示：

- 当前播放和待播歌曲
- 歌曲对应的视频画面/缩略图
- 当前绑定的灯光预设
- 播放进度、已播放时间和剩余时间
- Deck 1 与 Deck 2 的加载、待播、播放和错误状态
- 两首歌曲之间的 Crossfader 与手动过渡状态

## 2. 布局

```text
┌───────────────────────┬─────────────┬───────────────────────┐
│ Deck 1                │  Transition │ Deck 2                │
│ 歌曲 / 视频 / 灯光    │             │ 歌曲 / 视频 / 灯光    │
│ 进度 / 时间 / IN-OUT  │ Crossfader │ 进度 / 时间 / IN-OUT  │
│ 播放控制 / 状态       │ Manual      │ 加载候选 / 播放控制   │
└───────────────────────┴─────────────┴───────────────────────┘
```

- C2 顶部不设置“⚡ 双曲无缝衔接”标题栏，也不在顶部设置与其同一行的“自动/手动”按钮
- 删除顶部整行后释放的高度全部归还 Deck 1、Transition 和 Deck 2 主体，使歌曲信息、波形、进度及播放控制获得更充足的垂直空间
- 当前首版固定使用手动过渡；未来如增加自动衔接，只能作为 Transition 内部的受控高级功能呈现，不得重新占用 C2 全宽标题行
- Deck 1 和 Deck 2 左右对称
- 中间过渡区宽度小于两侧 Deck，放置 Crossfader、手动过渡提示和必要的过渡时间信息
- Deck 1 与 Deck 2 是相互独立的播放器，可以单独播放、暂停，也可以同时播放并重叠输出
- 正在播放的 Deck 显示 `ON AIR`，仅完成装载的 Deck 显示 `READY`；两侧可以同时显示 `ON AIR`，不能假设任一时刻只有一个 Deck 播放
- 哪个 Deck 作为主要输出不固定；Crossfader 决定两者在最终音频中的相对音量，但不等同于强制暂停其中一侧
- 首次进入首页的默认安全状态是 Deck 1 `ON AIR`、Deck 2 待命；Deck 2 用于装载下一首候选，不因被装载而自动发声

### 2.1 手动装载与大厅声音隔离

- 从 L 区通过数字 `1` 或 `2` 选择歌曲，只会把该歌曲装载到对应 Deck；这是候选准备操作，不是播放或切换命令
- 装载完成后，目标 Deck 的进度固定重置为 `00:00`，完成解码预热后保持 `READY/暂停`，直到操作员按下该 Deck 右上角唯一的播放/暂停主按钮
- 装载动作绝不自动开始目标 Deck 播放，绝不暂停或替换另一 Deck，绝不移动 Crossfader，绝不改变大厅主输出的音量比例
- 装载动作也不得改变 C1 的 LED 节目预览或正式输出；音频过渡和视频切换均需由操作员在各自控制项中明确执行
- Deck 1、Deck 2 的播放/暂停按钮与 Crossfader 都是人工控制项。即使 Deck 2 已准备好下一首，Deck 1 仍继续按原状态输出，直至操作员手动启动 Deck 2 并手动混音

### 2.2 Deck 颜色语义

- Deck 1 维持绿色主题；Deck 2 使用统一蓝色主题，两者的编号颜色在 L 区歌曲状态中保持一致
- Deck 1 的标题、状态文字/指示、封面强调、波形、播放键、操作提示、边框和激活背景统一使用绿色体系
- Deck 2 的标题、状态文字/指示、封面强调、波形、播放键、操作提示、边框和激活背景统一使用蓝色体系
- Deck 2 不得只更换封面或单个图标颜色；整个 Deck 2 区域内所有表达所属关系和交互状态的强调色都应使用蓝色
- Deck 2 两行控制按钮的 Default、Hover、Pressed、Selected 四种状态必须全部使用蓝色系列令牌；默认背景也不得继承 Deck 1 或全局绿色按钮背景
- Deck 2 的四种状态在蓝色体系内使用清晰的明暗、边框和填充层级区分；只有禁用、故障与危险语义可以使用全局对应颜色
- 中性色文字、禁用态、故障红色和危险操作色可继续共用全局令牌，不强制染成 Deck 色
- Crossfader 左侧 Deck 1 数值使用绿色，右侧 Deck 2 数值使用蓝色；滑块位置或填充应能同时清楚表达两侧的颜色归属
- 两个 Deck 同时播放或同时激活时，各自保留完整主题色，不用单一 `ON AIR` 颜色覆盖另一侧

## 3. 单个 Deck 显示内容

- `DECK 1` / `DECK 2` 标题字号相对当前版本增大，保证暗场和远距离操作时能快速识别两侧 Deck
- 歌曲名、歌手和歌曲来源
- 视频缩略图及画面来源：原 MP4、自有视频或默认背景
- 灯光预设名称及连接/触发状态
- 当前原声/伴唱状态
- 波形或简化时间轴
- 当前时间、总时长和剩余时间
- 每个 Deck 的音量比例条下方显示该歌曲的音频波形；Deck 1 波形使用绿色，Deck 2 波形使用蓝色
- 波形相对上方音量刻度适当下移，在音量刻度与波形之间增加清晰的垂直间距，避免两个高密度图形粘连或被误认为同一个控件
- 波形展示整首歌曲的降采样峰值，并叠加当前播放位置；它用于快速识别强弱段落和播放进度，不替代精确时间读数
- 波形必须与真实歌曲播放进度一一对应，播放引擎返回的媒体时钟是唯一进度来源；固定中央线始终代表当前实际播放位置，不使用与歌曲进度脱钩的循环假动画
- 使用约 `24×` 的 DJ 时间窗口：只显示当前位置附近约十秒内的较短片段，因此每秒真实进度在屏幕上的移动距离更大；歌曲真实播放速度、进度和时间读数不变
- 波形使用 Canvas 绘制，而不是为每个峰值创建网页柱状元素。渲染器只从缓存峰值中取出当前 `24×` 窗口可见的部分绘制，并按实际媒体时钟刷新，以避免双 Deck 数千 DOM 节点、渐变与发光重绘导致控制台卡顿
- Canvas 的视觉刷新可以按显示帧率插值，但不得自行推进播放位置；下一帧位置始终由播放器已确认的实际进度校正
- 操作员按住波形拖动时，固定中央线准确表示目标定位；松开后提交 seek，并继续从播放器实际位置滚动
- 缩放只改变可视时间密度与移动速度，不改变歌曲真实播放进度、时间换算或 `seek` 目标；固定中央播放指示线仍代表实际当前位置
- 波形同时作为可交互的进度定位区：鼠标按住波形并左右拖动时，实时预览目标进度和对应时间；松开鼠标后才向对应 Deck 提交一次 `seek`
- Deck 1 与 Deck 2 的波形拖动、预览位置和 `seek` 命令完全独立；操作一侧不得改变、暂停或跳转另一侧
- 正式产品读取后端为真实媒体生成的缓存波形；原型没有真实文件时，只能使用明确标注为“演示峰值”的模拟数据，不能伪装成歌曲分析结果
- `IN` 开始点、`OUT` 混出点
- 每个 Deck 只保留一个独立的播放/暂停主按钮，并固定放在 Deck 右上角，直接替代原“正在播放/已就绪”状态文字的位置；按钮改为略大的圆形，提高主操作辨识度和命中面积
- 右上角同一按钮根据该 Deck 实际状态在播放与暂停图标间切换，同时承担主要状态表达
- 播放中：Deck 1 圆形主按钮使用绿色，Deck 2 使用蓝色；只有确认处于播放状态时才显示对应 Deck 主题色
- 暂停状态：Deck 1 与 Deck 2 的圆形主按钮统一使用橙黄色，不保留绿色或蓝色播放态，避免把暂停误认为正在输出
- Deck 下方采用两行紧凑统一控制区，每行保留四等分网格，但 8 个控制均为相互独立的 R 角按钮
- 第一行为 transport：上一首 / 重放 / CUE / 下一首；四个按钮等宽排列，按钮之间保留清晰间隙以避免暗场误触
- 第二行为四个纯图标播放模式：单曲播放 / 单曲循环 / 顺序播放 / 随机播放；四个按钮与第一行列位置对齐，同样采用独立 R 角外形
- 取消按钮之间的贯通切割线和连续分段控件外观；每个按钮都有完整边界、独立 Hover/按下/选中状态和足够命中区域
- 两行 8 个 R 角按钮在现有基础上增加统一高度和纵向命中面积，保证暗场、触控和快速操作时易于点击；两行仍须完整容纳在 Deck 内部
- 按钮组底部留白与按钮组左右留白使用同一间距令牌，形成均衡的三边安全距离；不再使用“紧贴底边且无底部留白”的旧规则
- Deck 1 使用绿色状态主题，Deck 2 使用蓝色状态主题
- 第一行不再放置重复的播放/暂停按钮；唯一播放/暂停主按钮仍位于 Deck 右上角，两行控制区不得与其形成视觉竞争
- `CUE` 表示预听/定位点：用于在指定位置准备、试听待播歌曲，专业使用中通常送往操作员耳机监听通道，而不是直接送往大厅主输出
- 首版若尚未接入独立耳机监听通道，`CUE` 必须明确标记为“预留”或禁用态，不得让操作员误以为点击后可安全预听，也不得把预听声音误送到大厅
- 重新加载和卸载如需保留，应降为次级菜单操作，不得增加第二个播放入口
- 候选歌曲装载状态；实际歌曲选择由首页 L 区完成

## 4. 候选歌曲流程

1. 一个 Deck 正在 `ON AIR`；另一 Deck 也可以已在播放，或处于 `READY` 等待启动。
2. 操作员在首页 L 区选择另一个 Deck 对应的 1号/2号曲库。
3. 从当前已发布歌单中选择并装载候选歌曲。
4. 系统检查音频、视频、灯光和 IN/OUT 点，完成解码预热。
5. 目标 Deck 的进度归零为 `00:00`，显示 `READY/暂停`；此时 Crossfader、大厅声音、另一 Deck 的状态和 C1 节目均保持不变。
6. 操作员决定何时手动按下目标 Deck 的播放/暂停主按钮，并手动调节 Crossfader；首版不提供由系统代替操作员启动 Deck 或移动推子的自动流程。
7. 操作员可随时更换候选，不影响当前 Deck 播放。

首页不提供歌曲搜索、上传或新建。搜索整个本地音乐库属于“音乐管理”页面；首页候选选择统一在 L 区当前歌单中完成。

## 5. 无缝衔接

默认且首版仅采用人工过渡。L 区装载候选歌曲不会触发本节任何步骤；自动衔接是后续可评估能力，当前不得启动 Deck 或移动 Crossfader。

每首歌保存两个混音标记：

- `IN`：新歌曲真正开始参与播放的位置，可跳过不需要的前奏或空白
- `OUT`：旧歌曲开始交给下一首的位置，可跳过不需要的结尾或长尾

手动无缝衔接过程：

1. 操作员根据当前曲目 `OUT` 点和待播 Deck 的 `IN` 点决定合适时机。
2. 操作员手动按下待播 Deck 的播放/暂停主按钮，使待播 Deck 从指定位置开始播放。
3. 两首歌在操作员决定的时间内重叠输出。
4. 操作员手动拖动 Crossfader；系统只按当前位置计算两侧等功率音量比例，不自行移动推子。
5. 视频按操作员明确执行的方式交叉淡化或切换。
6. 灯光在操作员明确触发的开始、中点或结束时机切换下一预设。
7. 过渡完成后，新 Deck 保持 `ON AIR`；旧 Deck 是否暂停、卸载或继续播放均由操作员决定，双 Deck 同播能力保持可用。

## 6. 控制项

- Crossfader：手动拖动，位置从 Deck 1 到 Deck 2
- Crossfader 只响应操作员在 C2 的鼠标、触控或键盘操作；任何 L 区歌曲装载、Deck 候选替换或预热完成事件都不得改变其位置
- Deck 1/2 的右上角播放/暂停主按钮是各自唯一的启动/停止入口；装载候选、切换 L 区曲库和切换歌单均不得隐式触发它
- 每个 Deck 的独立播放模式：单曲播放、单曲循环、顺序播放、随机播放
- 自动衔接：后续能力；首版不显示可用开关，不能代替操作员按下 Deck 播放键或手动移动 Crossfader
- 过渡时间：3 秒、5 秒、8 秒和自定义
- 立即衔接：仅作为引导操作员开始手动过渡的提示，不得自动播放、自动移动 Crossfader 或切换大厅声音
- IN/OUT 编辑：在时间轴上拖动，支持试听后保存到歌曲默认配置
- 条目覆盖：本次歌单可以覆盖歌曲默认 IN/OUT，不影响其他歌单

### 6.1 Deck 独立播放模式

- 不设置全局播放模式；Deck 1 与 Deck 2 各自提供一组固定模式：单曲播放、单曲循环、顺序播放、随机播放
- 同一个 Deck 内四种模式互斥，任一时刻只能有一个模式处于选中状态；Deck 1 和 Deck 2 默认均为“顺序播放”
- 两侧模式相互独立，可以同时选择不同模式，例如 Deck 1 为单曲循环、Deck 2 为随机播放；切换一侧不得改变另一侧
- 四种模式按钮在 Deck 主界面中不显示文字，只显示业内常见音乐播放器图标，语义依次为单曲播放、单曲循环、顺序播放、随机播放；每个图标必须提供可访问名称或悬浮提示，不能仅依赖图形让新操作员猜测
- 模式按钮构成两行统一控制区的第二行，与第一行 transport 同为四等分、列位置对齐；8 个按钮均为带间隙的独立 R 角按钮，不使用贯通切割线；按钮采用增加后的统一高度，按钮组底部留白与左右留白一致，并通过 Deck 内部自适应保证不挤压波形区域
- Deck 1 的模式选中态使用绿色主题，Deck 2 的模式选中态使用蓝色主题；未选中、Hover、按下、禁用状态不得与选中状态混淆
- 第二行播放模式的 Selected 状态必须使用四边完整高亮描边，并叠加同色低透明度背景；不再采用仅点亮按钮底边的选中表达
- Deck 1 使用完整绿色描边与绿色轻背景，Deck 2 使用完整蓝色描边与蓝色轻背景；描边在四个圆角处连续闭合，不得被相邻按钮或容器裁切
- 每组模式仅作用于对应 Deck 的队列行为，并与该 Deck 的独立播放/暂停主按钮配合
- 切换模式后应立即显示已生效状态并持久化到对应 Deck 的当前播放会话；模式切换本身不应中断正在播放的歌曲

### 6.2 Crossfader 视觉与交互

- Crossfader 采用专业 DJ 台式刻度设计，不使用普通网页 Range 滑条外观；以中央长刻度为分界，左侧刻度全部使用绿色系列，右侧刻度全部使用蓝色系列，主要刻度使用更亮的同系颜色
- 轨道上下或沿轨道均匀排列短竖向刻度；中央 `50%` 位置的刻度明显加长，帮助操作员在暗场快速归中
- 横穿刻度中央的滑动轨道保持细窄，取消灰色描边并明确分为左半绿色、右半蓝色；推子帽使用加高的实体矩形，左半块为亮绿色、右半块为亮蓝色，中间使用一条窄白线，不使用大面积灰色或浏览器默认圆形滑块
- Crossfader 整个底栏及刻度区域需要适当加高；获得键盘焦点时不得在滑动区域外绘制矩形线框，只允许推子帽自身显示焦点反馈
- 左侧 Deck 1 端及其百分比使用绿色，右侧 Deck 2 端及其百分比使用蓝色；中间区域保持中性暗色，避免暗示只能激活一个 Deck
- 左右两侧不显示“1号 / 2号”文字；最左使用与歌单一致的绿色实心圆 `1`，最右使用蓝色实心圆 `2`，两个音量数值放在圆形内侧并靠近滑轨，不显示 `%` 符号；左右数值统一使用品牌副标题的灰绿色和略小字号，拖动时数值即时更新
- 两个 Deck 内的绿色/蓝色条表示实际输出音量比例，不使用固定演示宽度；Deck 1 实时显示 `100 - Crossfader`，Deck 2 实时显示 `Crossfader`，拖动推子时两条同步反向增减，对应 Deck 暂停后其音量条归零
- 音量条下方的音频波形使用高密度细采样线；中央固定一条高对比竖向播放线，播放时波形从右向左经过该线，中央线始终代表当前播放位置，暂停时波形停止移动
- 拖动定位期间仍保留固定中央播放指示线和波形从右向左流动的视觉语义；波形随拖动展示预览位置，松开提交后再以实际播放器返回的位置校正，避免 UI 自行假定跳转成功
- 拖动范围、等功率交叉淡化计算和现有控制逻辑保持不变；本项只改变操作外观、刻度可读性和两侧颜色归属
- 键盘、触控和鼠标拖动都必须可用，推子帽命中区域可大于其可见矩形，但不能改变视觉轨道厚度

## 7. 首版边界

- 支持可靠的重叠播放和音量交叉淡化
- 支持人工设置 IN/OUT 点并自动保存
- 可通过静音/低能量检测提出 IN/OUT 建议，但必须允许人工校正
- 首版不承诺自动节拍对齐、变速不变调、搓碟和专业 DJ 效果器
- 没有 BPM 对齐时，系统实现的是平滑无间隙衔接，不宣称专业 DJ 混拍
- 每个 Deck 底部保持两行控制，但每行由 4 个增加为 5 个并严格等分：第一行新增独立歌词开关，显示“词”；第二行新增“原唱 / 伴唱”切换，直接显示当前模式
- “词”使用 12px 加粗文字，“原唱 / 伴唱”使用 10px 加粗文字，必须在控制台正常观看距离下清晰可辨
- Deck 1 与 Deck 2 的歌词显示、原唱/伴唱状态分别保存、互不影响；切换候选 Deck 不得改变另一个 Deck 的状态
