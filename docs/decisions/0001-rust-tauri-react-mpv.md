# ADR 0001：采用 Rust、Tauri 2、React/TypeScript 与 mpv

状态：已接受

日期：2026-08-18

## 背景

KING CLUB 播控软件运行在 Windows 主控电脑，需要管理至少 8 小时的连续播放、异形 LED 第二屏、歌曲和视频组合、原声/伴唱、歌单、Qu-16、Tiger Touch Pro，以及后续手机点歌和弹幕。

UI 是朴素的专业控制台，主要由按钮、表格、歌单编辑、预览和设备状态组成。正式视频输出必须与 UI 隔离，避免界面异常影响 LED 主屏。

## 决策

项目采用以下主技术栈：

- Rust stable/MSVC：核心业务、状态机、播放编排、设备适配、恢复和日志
- Tauri 2：Windows 桌面应用外壳与安全 IPC 边界
- React + TypeScript + Vite：控制台 UI
- mpv 独立进程：音视频解码、音轨控制和显示器输出
- SQLite：本地持久化
- Axum：后续局域网手机服务

Tauri 的 WebView2 只渲染控制界面，不承担 LED 视频播放。Rust 核心通过受控命令接口管理独立 mpv 进程；正式输出进程与控制台生命周期解耦。

## 职责边界

### React/TypeScript

- 页面布局、按钮、表格、歌单编辑和状态展示
- 不直接访问数据库、文件系统、设备或 mpv IPC
- 不保存权威播放状态

### Tauri/Rust 主控

- 校验 UI 命令并返回真实执行状态
- 歌单、素材、配置和日志管理
- 播放状态机与恢复点
- Qu-16 和 Tiger Touch Pro 适配器
- 显示器发现和输出目标管理
- 启停、监控和恢复 mpv 进程

### mpv

- 硬件加速解码
- MP4/MP3 等媒体播放
- 音轨、声道、暂停、跳转和循环
- 指定 Windows 显示器全屏输出
- 通过 JSON IPC 接收命令和报告状态

## 候选方案

### .NET/WPF

Windows 集成成熟，但与后续 Web/手机界面的技术复用较少，未选为主方案。

### Qt/QML

GPU 场景图和 Windows 支持成熟，但与 Rust 组合需要额外 C++/FFI 边界，并增加 Qt 部署与许可管理。当前控制台不需要其复杂动画能力。

### Electron

Web 开发生态成熟，但会自带 Chromium；相较 Tauri 体积和资源占用更高。

### 纯 Rust UI

可减少 WebView 依赖，但当前大量表格、搜索和表单使用 React/TypeScript 开发维护效率更高。

## 影响

### 正面

- Rust 核心可支持严格状态管理和长时间运行
- UI 与播放输出隔离
- 控制台开发效率高，后续手机端容易共享类型和设计思路
- 可为 DJ 小屏启动额外播放实例
- 不需要浏览器窗口或公网，Tauri 资源均可本地打包

### 代价与风险

- Windows 需要 WebView2 Runtime
- mpv 作为随应用分发的第三方二进制，需要固定版本并保存其许可声明
- 多文件音视频同步、实时预览和无黑帧切换必须用真实素材验证
- UI、Rust 与 mpv 之间需要清晰的命令版本和错误协议

## 验证门槛

在进入完整功能开发前，技术样机必须验证：

1. Tauri 控制台可管理指定第二屏上的独立 mpv 输出。
2. 支持完整 MP4、MP4 音频加替换视频、MP3 加循环视频。
3. 原声/伴唱切换不重新开始歌曲或画面。
4. 暂停、跳转、循环、下一首及安全黑场可可靠执行。
5. UI 重启或 mpv 异常时行为符合安全设计。
6. 使用真实素材完成至少 8 小时连续播放测试。

验证失败优先调整 mpv 集成方式或媒体组合实现，不轻易改变已选主技术栈。只有存在无法满足验收标准的硬性问题时，才通过新的 ADR 替代本决策。
