- [已确认] Rust + Tauri 2 + React/TypeScript + mpv 主技术栈
- [已确认] 开发机采用 mpv x86-64-v3；正式酒吧主控机和生产发布以 x86-64-v4 为目标，采购 CPU 必须支持 AVX-512
- [待完成] 自行构建并固定 mpv x86-64-v4 版本、依赖与 SHA-256，在目标酒吧主机完成硬件解码和长时稳定性测试
- [已完成] 两个真实 mpv Deck 的加载、播放/暂停、Seek、音量和 Crossfader IPC 技术验证
- [已完成] Windows Job Object 托管 mpv 子进程，并通过强制结束主程序的 Windows 实测验证自动回收
- 用真实电脑、屏幕和素材验证 Rust + Tauri 2 + mpv 技术样机
- 验证双 Deck 预加载、Crossfader 与音视频平滑过渡
- 验证 Qu-16 和 Tiger Touch Pro 控制链路
- 获取候选音乐供应商的书面授权范围、API 文档和测试账号
- 确认应用形态、控制边界、通信协议与部署方式

## 阶段 3：MVP 开发

- [已完成] 自动建立并轮询扫描本地 MP4/MP3/图片媒体目录
- [已完成] 提取文件名、分类、时长和可用音频标签元数据
- [已完成] MP3/FLAC 导入后后台生成真实波形、BPM、Beat、Downbeat 与 Bar 网格；结果按文件指纹和算法版本持久缓存，Deck 装载时不得重复分析
- [已完成] 下载/复制中的音频先经过稳定性确认再加入曲库和串行分析队列；运行中新增歌曲按文件路径重映射 Deck，不因列表排序变化打断当前播放
- [已完成] 长音频波形改为“按时长增加峰值总数 + 固定约 12 秒可视窗口 + Canvas 按像素抽样”，解决一小时歌曲被压成密集条纹及移动速度过慢问题
- [已完成] 波形分析 v4 改为 RMS 能量与瞬态峰值混合包络，保留安静段、乐句和鼓点强弱；分析队列改为扫描只追加、不取消，完成后自动刷新对应 Deck
- [已完成] Deck 波形使用整首歌曲固定动态范围与瞬态增强；每个峰值锚定绝对媒体时间，只让固定波形连续平移经过中央播放线，避免逐帧按屏幕列重采样造成形状抖动；Beat/Downbeat/Bar 改在波形上层显示，长舞曲半拍 BPM 自动翻倍，并在检测点过稀时补齐可视节拍网格
- [已完成] 建立 SQLite 音频分析表，迁移原文件缓存并保存波形/节拍状态、失败原因和算法版本；后续曲库、歌单和歌词表继续在同一数据库演进
- [已完成] Deck 节拍网格人工校正：可修改 BPM、拍号、设置当前播放位置为小节第一拍并按 10 ms 微调；校正结果独立持久化并覆盖自动分析网格
- [待开发] 在真实歌曲上完成节拍网格校正验收，并增加半拍/双倍 BPM、Tap Tempo、网格整体拖动和逐段变速歌曲支持
- [已确定] 开发阶段 ASR 固定使用 `Qwen/Qwen3-ASR-1.7B`，词级时间轴使用 `Qwen/Qwen3-ForcedAligner-0.6B`，Python 固定为项目隔离的 3.12 环境；不自动降级到 Qwen3-ASR-0.6B
- [已完成] 建立 `ai_analysis_jobs` 持久化任务表、内容采样指纹、模型/管线版本和独立派生目录；稳定进入曲库的歌曲按串行顺序登记，同一内容重复扫描或改名不会建立重复任务
- [已完成] 建立项目隔离的 Python 3.12 AI 工作器并把并发固定为 1；Qwen3-ASR-1.7B 与 ForcedAligner-0.6B 权重已通过 ModelScope 下载到项目本地缓存，运行时优先读取本地目录，不依赖临时联网
- [已完成] 歌词与原伴唱导入管线首轮端到端验证：Demucs 持久化 `vocals.flac`/`no_vocals.flac`，Qwen3-ASR-1.7B 生成歌词，ForcedAligner-0.6B 生成 LRC 与逐词 JSON，最终状态写回 SQLite。当前 4 分 41 秒中文样本在 i7-9750H/16 GB CPU 环境总耗时约 10 分 18 秒，320 个词级时间项覆盖 0.32–242.16 秒；识别结果仍需人工校正入口
- [已完成] 开发版独立 Python 工作器随桌面应用启动，以 Windows Idle 优先级和单任务循环只消费 `queued` 任务；日志单独写入应用日志目录，应用退出时回收进程。正式安装包仍待设计 Python、模型权重及许可证的离线分发方式
- [已完成] `ready` 派生歌词接入曲库与 C1/第二屏，同名人工 LRC 优先；`vocals`/`no_vocals` 路径随歌曲对象进入 Deck。原唱/伴唱按钮已真实切换原始音频与 `no_vocals.flac`，mpv 后端原子保持播放位置、暂停状态和 Crossfader 音量，且不影响另一 Deck；真实 MP3→伴奏 FLAC 切换测试通过
- [待开发] 优先采用人工/供应商正式伴奏并记录来源优先级；增加歌词人工校正与伴奏质量审核。正式多音轨播放代理完成后，可在同一容器内按 mpv 音轨 ID 切换，进一步降低不同文件切换的瞬时延迟
- [已完成] 真实 MP4 在 C1 解码播放，PVW 锁定后必须确认才进入 PGM
- [已完成] 视频自身音轨默认静音且可独立开关，不改变 Deck 或 Crossfader
- [已完成] Deck 1/2 使用两个真实 mpv V3 进程独立加载、播放、暂停和 Seek
- [已完成] 手动 Crossfader 使用等功率曲线控制两个 mpv Deck，装载候选歌曲不自动播放、不移动推子
- [已完成] mpv JSON IPC 按 request ID 区分命令响应与文件事件，支持播放中可靠换歌
- [已完成] 单屏时隐藏独立输出窗口并保持 C1 实时预览；运行中轮询检测显示器热插拔
- [已完成] Windows Job Object 在主程序异常退出时回收全部 mpv 子进程
- [已完成] 开发/兼容版 MSI/NSIS Release 构建，将固定版本 mpv V3 随安装包分发
- [待完成] 生产版 MSI/NSIS 改为随包分发经校验的 mpv V4，安装前检测 CPU 指令集并拒绝不兼容主机
- [已完成] 第二屏安全选屏逻辑测试：单屏回退 C1、自动排除主控屏、主控窗体换屏、无效屏号、断屏旧配置与无法识别主控屏时停止输出
- [已完成] 在物理第二屏完成 3840 × 2160、300% DPI 独立 PGM 实测：8:9/T 形画布、真实 MP4、无标题栏/任务栏/圆角、C1 同步预览均正常
- [已完成] 实测从扩展屏切回单屏时输出自动隐藏、C1 保持工作；恢复扩展屏后无须重启即可自动回到第二屏，物理尺寸仍精确匹配
